# Terminal-Lego-15k vs Terminal-Bench 2: contamination check

**Verdict: usable after dropping 31 tasks** (`exclude_tasks.txt`). No Terminal-Lego (TL) task is a copy of any TB2 task. No instruction text overlaps, no TB2 canary appears, and none of the distinctive TB2 artifacts show up. The hits are StackOverflow-level skill neighbours. I dropped the closest ones and kept a watch list. Ten of the 31 drops are neighbours of the held-out 20, and 5 of the held-out 20 have at least one dropped neighbour. The other 15 held-out tasks have no candidate beyond loose topic overlap.

## Dataset

- **Repo:** `Lego-X/Terminal-Lego-15k`. `SWE-Lego/Terminal-Lego-15k` redirects to it. Revision `9c197f1c` (2026-06-04). Apache-2.0. Paper arXiv 2606.03461. Code at github.com/SWE-Lego/terminal-lego (MIT).
- **Size:** the card says 15,389 verified tasks, but the repo has **15,049 task dirs**. 15,048 are complete; `task_00015` has no instruction or toml. The extra 340 were never uploaded.
- **How we got it:** the repo is about 120k loose files. We used `hamishivi/agent-task-terminal-lego-15k`'s `task-data.tar.gz` (56 MB) instead. It holds all 15,048 complete dirs byte-for-byte, pinned to the same revision, and its sha256 matches that repo's `validation.json`. Raw data is in `data/` (gitignored).
- **Prime mirror:** `PrimeIntellect/Terminal-Lego-15k` has 13,825 tasks with prebuilt Prime images. It dropped 1,224 tasks for quality reasons (no-op pass 234, oracle failures 520+116+96+..., image build timeout 242). None of its exclusions are for decontamination. 3 of our 31 are already gone from it, so it needs 28 more drops.
- **Per-task files:** `instruction.md`, `task.toml`, `environment/Dockerfile` (+ `task_file/` inputs), `solution/solve.sh`, `tests/test.sh`, `tests/test_outputs.py`.
- **task.toml fields:** `metadata.{author_name="StackOverflow Community", author_email, difficulty, category, tags, source_url, source_score, expert/junior_time_estimate_min}`, `verifier.timeout_sec`, `agent.timeout_sec`, `environment.{build_timeout_sec, cpus, memory, storage}`.
- **Difficulty:** easy 9,839 (65.4%), medium 5,022 (33.4%), hard 187 (1.2%).
- **Category (9 values):** general 7,095, programming 4,480, system-administration 993, version-control 702, shell-scripting 657, database 448, web-server 306, networking 229, containerization 138.
- **Tags:** 4,681 distinct. Top tags: python 4,480, linux 1,049, bash 952, c# 740, git 732, javascript 670, pandas 634, http 524, algorithm 502, numpy 497.
- **Source:** 100% stackoverflow.com question URLs. Median question score is 114 (p10 37, p90 566). Median instruction length is about 420 words.
- **Shape:** these are mostly short, single-concept tasks under `/app/task_file/`, often "demonstrate X" or "fix error Y". They are much easier and narrower than TB2.

## Decontamination and license notes

- **Upstream decontamination:** neither the dataset card, the GitHub README, nor the paper mentions decontamination against TB2/TB2.1. The only dedup is by StackOverflow question ID, across their own crawls (paper appendix A.2). The generator prompts use TB2's file layout and a canary-string template but no TB2 tasks as examples.
- **Canaries:** every TL file carries a "terminal-bench-canary GUID" line with a synthetic per-task GUID such as `xxxxxxxx-0000-0000-0000-<qid>`. TB2's real GUID `26b5c67b-...` appears in **0** TL files.
- **License:** the whole dataset is declared Apache-2.0, and there is no per-task license field. Two caveats:
  1. Each task is an LLM rewrite of a StackOverflow Q&A. User content there is CC BY-SA, so attribution and share-alike may arguably carry over. `source_url` gives per-task attribution.
  2. The paper says the task text, environments, solutions and tests were generated by **claude-opus-4-6**. If the Smart Data or commercial use matters, check the provider's output terms.

## Method (`decontam.py`)

All checks compare the 15,048 TL tasks against the 89 TB2 tasks, using local harbor cache instructions, solutions, tests and Dockerfiles.

- **(a) Name:** each TB2 slug is fuzzy-matched against TL titles and SO URL slugs. TL task ids are opaque (`task_NNNNN`), so this has no real signal.
- **(b) Text:**
  - **Word 13-grams on instructions:** **0 hits for all 89 tasks.**
  - **13-grams on full text (instruction + solution + tests + Dockerfile):** 39 TB2 tasks have a hit after dropping boilerplate grams (seen in more than 25 TL tasks or in 2 or more TB2 tasks). All of them are shared code idioms (`for chunk in iter(lambda: f.read(4096)...`, Levenshtein loops, `app.run(host="0.0.0.0", port=5000)`), or apt/uv/pytest template lines. None is task text.
  - **TF-IDF cosine:** on instructions the best match per TB2 task has median 0.066 and max 0.230. On full text the median is 0.096 and the max 0.364, both from `openssl-selfsigned-cert`.
- **(c) Artifacts:** we extracted absolute paths, filenames and rare words that belong to one TB2 task and are rare in TL. We also ran a hand-picked keyword list per held-out task (tables in `auto_matches.md`). These distinctive held-out artifacts have zero TL hits: `povray`, `compcert`, `doomgeneric`, `mteb`, `bge-small`, `pystan`, `rstan`, `metacircular`, `trunc.db`, `distilbert…sst-2`, `vectorops`, `climate_analyzer`, `dhfr`/`gblock`, `cli_tool`, `user.cpp`.
- **Hand review:** I read the top 3 or more candidates per held-out task (pooled from instruction TF-IDF, full-text TF-IDF, 13-grams, artifacts and keywords). I also grepped TL for each held-out task's core technique, e.g. `git fsck` dangling recovery, `post-receive` deploy, gRPC, PyPI index, qemu, sqlite corruption, Scheme interpreters and CPU emulators.

**Verdict scale:**
- **same:** same setup and goal.
- **closely related:** the TL solution contains the TB2 solution recipe.
- **component:** the TL task's main deliverable is a distinctive piece of the TB2 task.
- **related:** skill or topic overlap only.
- **unrelated.**

**Exclusion policy:**
- Held-out 20: drop same, closely related and component.
- The other 69 TB2 tasks: drop same and closely related.

## Caveats

- These are lexical checks plus hand review, not embeddings. A paraphrased near-duplicate with different vocabulary could slip past TF-IDF. The per-task keyword greps on core techniques are the backstop.
- The tasks are LLM-generated from StackOverflow, not scraped from TB2, so the risk is skill overlap, not leakage. TB2 tasks that are themselves canonical StackOverflow questions (openssl cert, detached-HEAD recovery, nginx logging, gRPC hello-world) are the ones with real neighbours.
- TB2.1 was not checked separately. We used the local TB2 (2.0) task files and assumed 2.1 keeps the same 89 tasks.
