The source symlink points to the reviewed checkout; source-hashes.txt records changed files and the pod. parent/ contains a read-only git archive used for the shared parser comparison. CUDA_VISIBLE_DEVICES was empty for every execution that could load a model. Only the HF tokenizer was loaded. No GPU inference or CUDA build ran.

independent.py is a new seeded generator, not a modification of the earlier differential generator. Its 21,000 output mutations combine realistic terminal command strings, JSON-in-strings, unicode, quotes, backslashes, nested objects, Python literals, duplicate keys and parameters, multiple calls, unknown names, missing tool parameters, enum/anyOf/union/nullable/missing-type schemas and incomplete tags. Maximum raw output was 37,998 bytes and 12,755 tokens. Another 1,050 cases exercise multi-turn request preparation, content parts, system/developer/assistant/tool roles, missing and null fields, invalid argument JSON, scalars, arrays, duplicate keys and nonfinite numbers. The last 24 cases target literal boundaries and declared divergences. The seed is 0x72FE2243.

The oracle AST-extracts unchanged prepare/text_of/typed/split_output/error/chat definitions and constants from serve_exl3.py. It supplies the real HF tokenizer, a fake AsyncJob yielding tokenizer-decoded text, and inert sampler/tensor stubs. It uses JSONResponse for HTTP JSON encoding and the actual chat coroutine's SSE strings. SSE strings are UTF-8 encoded to detect serialization failures. No parser or response logic is copied from the Zig implementation. FastAPI dependencies are installed only under deps/ because exl3-local lacks FastAPI. deps.log records exact package versions. The required interpreter is Python 3.12.14.

routes.zig supplies those same generated token IDs to a scripted engine, then invokes openai.run through ClientOut and Conn.write_hooks. These are the production HTTP serializers; this is a socket-free CPU test, not a running GPU server. It captures full wire writes and the prompt token IDs actually submitted. Comparison strips HTTP headers and replaces only random completion/tool IDs and creation timestamps. Every other JSON/SSE body byte remains significant. The oracle uses identical decoded chunks through the first thinking-close marker. Later text can be coalesced because the pod emits no further reasoning deltas. No network-timing keepalive comparison is claimed.

Main result: 22,074 engine records; zero missing. 21,844 cases produce serializable reference bodies. Of these, 53 JSON and 53 SSE bodies differ. The same cases fail both formats: 47 named Unicode escapes, four malformed hex/codepoint escapes, two embedded-NUL cases. Of 230 reference exceptions, 224 are invalid scalar/array/null history arguments rejected by HF's items filter. The engine rejects those before submission with HTTP 400. Five are documented unsupported literal values or keys; one is an unpaired surrogate's UTF-8 encoding failure. All 826 renderable synthetic history token sequences match exactly.

The follow-up targeted.py uses actual tools from an existing EXL3 TB2 pi pilot. It reconstructs 55 first/middle/last sampled histories, converting the trace's flat function calls to OpenAI's nested function representation. All 55 histories, JSON bodies and SSE bodies match; the longest prompt has 94,967 tokens. Six minimized cases fail in both formats, while three correctly escaped/raw-string controls pass. minimal-repros.json contains complete inputs and both byte outputs. These 64 follow-up cases are separate from the main corpus counts.
